# Rogue Domain 规则契约

> 状态：最小可玩 Domain v0.1  
> 更新日期：2026-07-30  
> 代码位置：`Assets/Game/Experimental/Rogue/Domain`

## 1. 文档目的

这份文档记录 Rogue 原型的纯规则层契约，供后续扩展当前项目或迁移到
新项目时复用。

`Domain` 不引用 Unity，负责确定性的地图、行动、战斗、回合、物品、
视野和快照规则。输入、动画、音效、GameObject、Tilemap 和存档文件
读写属于 Unity 或基础设施层，不应进入这里。

## 2. 核心状态

| 状态 | 职责 |
| --- | --- |
| `RogueGameState` | 协调地图、行动、战斗、敌人阶段、进程和视野 |
| `RogueMapState` | 保存地形、角色占位、地面物品和楼层出口 |
| `ActorState` | 保存阵营、位置、生命、攻击力和背包 |
| `TurnScheduler` | 维护玩家回合、敌人阶段、敌人顺序和轮次 |
| `VisibilityState` | 保存当前可见格与永久已探索格 |
| `RogueGameSnapshot` | 保存可序列化的稳定时刻数据 |

角色和物品分别使用 `ActorId`、`ItemId` 作为稳定身份。迁移或存档时，
不要用数组下标、显示名称或 Unity 实例 ID 替代它们。

## 3. 地图不变量

- 地图必须是正宽高的矩形网格。
- 新地图的所有格子默认可通行。
- 同一格最多存在一个角色。
- 地面物品不占用角色格，同一格可以存在多个物品。
- 角色只能被放在可通行且未被角色占用的格子。
- 已有角色的格子不能直接改为墙体。
- 出口必须位于可通行格。
- 越界格视为不可通行。

## 4. 回合契约

- 一轮由一个成功消耗回合的玩家行动，以及随后每个已登记敌人的一次
  行动构成。
- 被拒绝的行动不消耗回合，也不会启动敌人阶段。
- 敌人按照登记顺序行动。
- 敌人阶段开始后新增的敌人，从下一轮开始行动。
- 行动前被移除的敌人会被跳过。
- 角色死亡后必须同时从地图和敌人回合队列移除。
- 对非当前行动者提交行动时，行动被拒绝且状态不变。
- 玩家死亡或楼层完成后，所有后续行动都会被统一拒绝。
- `ResolvePlayer*Round` 系列入口会自动结算完整敌人阶段，并最终回到
  玩家回合，除非玩家在过程中死亡。
- 通过 `RogueGameState.RemoveActor` 移除角色时，地图和敌人回合队列
  会同步更新。
- 玩家成功消耗回合前会校准地图上的实际敌人与回合队列，避免新增或
  移除角色后出现行动名单漂移。

## 5. 行动规则

| 行动 | 成功条件 | 成功时消耗回合 | 失败时消耗回合 |
| --- | --- | ---: | ---: |
| 移动 | 目标为相邻的上下左右空格 | 是 | 否 |
| 撞击攻击 | 相邻目标属于敌对阵营 | 是 | 否 |
| 等待 | 当前行动者仍在地图中 | 是 | 否 |
| 拾取 | 物品在脚下且背包未满 | 是 | 否 |
| 使用治疗药 | 药在背包中且能实际恢复生命 | 是 | 否 |
| 丢弃 | 物品在背包中 | 是 | 否 |
| 下楼 | 玩家站在出口且地图上没有敌人 | 是 | 否 |

补充规则：

- 移动只允许曼哈顿距离为 1 的单步，不能斜走。
- 撞向敌人不会移动攻击者。
- 玩家与敌人互相敌对；中立阵营不与任何阵营敌对。
- 伤害等于攻击者的 `AttackPower`。
- 生命最低为 0；降到 0 时立即死亡并移出地图。
- 治疗不能超过 `MaximumHealth`。
- 满血使用治疗药会被拒绝，药物和回合都不会消耗。
- 拾取和丢弃是原子操作；失败时物品必须留在原来的容器中。

## 6. 敌人决策

当前敌人使用无随机数的最小策略：

1. 每回合向玩家靠近一个上下左右相邻格。
2. 优先选择与玩家距离更大的轴。
3. 两轴距离相同时，优先水平方向。
4. 首选方向被墙或其他非敌对角色阻挡时，尝试另一轴。
5. 两个方向都不可用时等待。
6. 如果目标格是玩家，则通过撞击规则进行近战攻击。

该策略用于验证回合闭环，不等同于最终寻路。替换为 A*、感知范围或
不同敌人策略时，不应修改移动和战斗解析器的基础契约。

## 7. 楼层进程

`RogueGameProgress` 包含：

- `Ongoing`：地图上仍有敌人。
- `FloorCleared`：地图上已经没有敌人，但尚未成功下楼。
- `FloorCompleted`：玩家在出口执行了下楼行动。
- `PlayerDefeated`：玩家已从地图移除。

玩家死亡优先级最高，其次是楼层完成。楼层是否清空以地图上实际存在的
敌人判断，而不是只检查回合队列。

## 8. 物品与背包

- 每个角色拥有独立且固定容量的 `InventoryState`。
- 容量可以为 0。
- 同一个背包不能存在重复 `ItemId`。
- 当前唯一物品类型为 `HealingPotion`。
- `EffectPower` 表示治疗量，必须为正数。
- 物品使用成功后从背包移除。
- 丢弃物品会把它放在角色当前格。

后续增加武器、装备、投掷物和状态效果时，应优先扩展物品效果解析，
不要让 Unity 组件直接修改角色生命或背包。

## 9. 视野与探索

- 视野以玩家位置和 `PlayerSightRadius` 重新计算。
- 使用确定性的网格射线判断遮挡。
- 不可通行格自身可见，但会遮挡它后面的格子。
- 当前可见格每次重新计算。
- 已探索格只增加，不会因为离开视野而清除。
- 玩家成功移动后自动刷新视野。
- 地图或视野半径发生外部变化时，可显式调用
  `RefreshVisibility()`。

## 10. 快照契约

只有满足以下条件时才能创建快照：

- 当前处于 `AwaitingPlayer`。
- 当前行动者是玩家。

快照包含：

- 地图尺寸和每格通行状态；
- 玩家 ID、全部角色、位置、阵营、当前/最大生命和攻击力；
- 背包容量与背包物品；
- 地面物品；
- 敌人登记顺序和当前轮次；
- 出口及楼层完成状态；
- 视野半径和已探索格。

当前快照是“序列化中立”的纯数据结构。它不负责：

- 选择 JSON、二进制或其他文件格式；
- 决定存档目录和文件名；
- 加密、压缩、云同步；
- 版本迁移和旧存档兼容。

这些职责应由 Domain 外部的存档适配器完成。

## 11. 复用方式

迁移到新项目时，优先整体复制：

1. `Domain` 目录及其 asmdef；
2. `Tests/EditMode` 中对应测试；
3. 本文档。

然后为新项目单独实现 Unity 适配层：

- 输入转换为 Domain Action；
- 把 Domain 位置映射到 Tilemap 或 GameObject；
- 根据 Action Result 播放动画、特效和音效；
- 把 `RogueGameSnapshot` 交给具体序列化器；
- 不让表现层绕过 `RogueGameState` 直接推进回合。

## 12. 当前有意未实现

以下内容不属于 v0.1 已完成规则：

- 随机或程序化地图生成；
- 多楼层 Run 容器和楼层之间的数据继承；
- 装备、技能、Buff、Debuff 和元素伤害；
- 远程攻击、投掷和范围效果；
- A* 寻路、仇恨、听觉和复杂敌人 AI；
- 饥饿、陷阱、商店和任务；
- 快照版本迁移和实际磁盘读写；
- 联机同步、回放和确定性随机数种子。

新增规则时，应同时更新本文档和 EditMode 测试。本文档建立时的测试
基线为 `39/39`。
