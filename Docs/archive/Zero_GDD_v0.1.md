# 《归零》可执行游戏设计文档

> 版本：0.1（Game Jam 原型基线）  
> 主题：COUNTDOWN  
> 类型：俯视角、网格制、确定性轻策略动作游戏  
> 一句话体验：把生命当作唯一货币，在每一步都让倒计时减少的地图上，算出一条仍能活着杀死 Boss 的路线。

---

## 1. 产品目标

### 1.1 玩家目标

玩家从数字 **100** 开始，在数字归零前：

1. 观察地图、敌人数字和危险范围。
2. 规划一条低消耗路线。
3. 击杀有收益的敌人，夺取其剩余数字。
4. 满足 Boss 门的开启条件。
5. 击败 Boss，且结算时玩家数字仍大于 0。

### 1.2 设计支柱

所有系统都必须服务于以下四点：

1. **数字就是一切**：生命、行动力、攻击成本和倒计时使用同一个数字。
2. **信息足够规划**：玩家应能在行动前看见成本、收益和危险，不靠猜。
3. **战斗是一笔交易**：敌人不是默认要清除的障碍，而是可能盈利、亏损或应该绕开的投资。
4. **归零持续施压**：每个有效行动都改变局面，禁止无成本试探和无限等待。

### 1.3 非目标

首个版本不制作：

- 金币、经验、装备、永久升级。
- 随机命中、暴击、闪避。
- 随机生成关卡。
- 复杂背包或技能树。
- 大量剧情分支。
- 需要记忆的隐藏伤害或隐藏敌人属性。

## 2. 核心规则总表

以下数值是首个可玩版本的默认值，必须做成可配置数据。

| 行为 | 玩家数字变化 | 目标数字变化 | 其他结果 |
|---|---:|---:|---|
| 移动 1 格 | -1 | 0 | 只能上下左右移动 |
| 普通攻击 | -2 | -2 | 敌人破防格 -1 |
| 受到普通伤害 | -10 | 0 | 可与行动成本同时发生 |
| 击杀普通敌人 | +敌人剩余数字 | 清零并移除 | 不得超过数字上限 |
| 原地等待 | -1 | 0 | 推进敌人回合 |
| 交互/开门 | 0 | 0 | 若移动进门格，移动本身仍花 1 |

默认参数：

| 参数 | 默认值 |
|---|---:|
| 玩家初始数字 | 100 |
| 玩家数字下限 | 0 |
| 玩家数字上限 | 199 |
| 移动成本 | 1 |
| 攻击成本 | 2 |
| 攻击对敌数字损耗 | 2 |
| 敌人命中伤害 | 10 |
| 普通攻击距离 | 曼哈顿距离 1 |
| 玩家每回合行动数 | 1 |

### 2.1 “18 → 6 → 12”的正式解释

敌人拥有两个公开属性：

- **数字储量**：显示在敌人头顶，可被夺取。
- **破防格**：用 1～4 个小图标表示击杀所需的有效攻击次数，不使用传统血条。

玩家每次普通攻击：

1. 玩家数字支付 2。
2. 敌人数字也减少 2。
3. 敌人破防格减少 1。

因此，一个数字 18、拥有 3 格破防的敌人：

- 玩家攻击 3 次，共支付 6。
- 敌人数字从 18 变为 12。
- 第 3 次攻击后敌人死亡。
- 玩家夺取剩余的 12。
- 不计算走位和受伤时，这场战斗使玩家净增 6。

数字 3、拥有 1 格破防的敌人：

- 攻击后敌人剩余 1。
- 玩家支付 2，再获得 1，战斗净亏 1。
- 如果还需绕路，亏损更大，因此通常不值得打。

### 2.2 行动合法性

- 玩家只能执行结算后仍至少剩 **1** 点数字的主动行为。
- 数字为 2 时不能发动成本为 2 的攻击。
- 数字为 1 时不能移动或等待。
- 受到伤害可以把数字降到 0；降到 0 立即失败。
- 击杀 Boss 的同一结算中，必须先支付行动成本。Boss 死亡后玩家数字大于 0 才胜利。

这保证目标是“在归零前”，而不是“与 Boss 同归于尽”。

## 3. 单回合结算系统

### 3.1 回合结构

游戏采用一步一回合的确定性结构：

1. **输入阶段**：玩家选择移动、攻击、等待或交互。
2. **预览阶段**：UI 显示本次行动的成本、预计结算数字和可能触发的反击。
3. **合法性检查**：检查目标、距离、阻挡和玩家剩余数字。
4. **支付成本**：先扣除玩家行动成本。
5. **执行玩家行为**：移动、攻击、交互。
6. **处理击杀与夺取**：死亡敌人的剩余数字转给玩家。
7. **环境结算**：门、机关、陷阱和胜负条件更新。
8. **敌人阶段**：所有已激活敌人各执行一个意图。
9. **最终胜负检查**：玩家数字小于等于 0则失败；Boss 已死且玩家大于 0 则胜利。
10. **生成下一回合意图**：刷新敌人头顶预告和玩家行动预览。

### 3.2 固定结算顺序

同一敌人阶段内，敌人按以下顺序行动：

1. Boss。
2. 精英/守门敌人。
3. 普通敌人。
4. 同类敌人按关卡中配置的 `TurnOrder` 从小到大。

不得依赖 Unity 对象遍历顺序。

### 3.3 输入锁

从玩家确认行动到所有动画和数字结算结束：

- 禁止接受新的游戏输入。
- 允许跳过或加速表现，但不能跳过逻辑。
- 逻辑结果先计算并保存，动画只负责展示。

### 3.4 验收标准

- 连续快速按键不会一回合移动多格。
- 同一局面、同一输入序列必定得到相同结果。
- 任何行动开始前，预览值和实际结算值一致。
- 动画加速或关闭不改变结果。

## 4. 玩家数字系统

### 4.1 数据

玩家至少包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| `CurrentNumber` | int | 当前唯一资源 |
| `StartNumber` | int | 关卡初始值 |
| `MaxNumber` | int | 默认 199 |
| `GridPosition` | Vector2Int | 所在格 |
| `Facing` | enum | 朝向，仅用于表现或攻击方向 |
| `State` | enum | Idle / Acting / Dead / Won |

### 4.2 唯一修改入口

所有数字变化必须通过统一接口，不允许其他系统直接写字段：

```text
ChangeNumber(amount, reason, source)
```

`reason` 至少支持：

- MoveCost
- WaitCost
- AttackCost
- Damage
- EnemyLoot
- Environment
- Debug

每次变化广播事件，供 UI、音效、镜头和统计系统订阅。

### 4.3 数字上限

- 默认上限 199，超出的夺取值直接损失。
- 击杀前预览必须显示实际可获得值和溢出值。
- 上限是关卡参数，方便测试无上限或 99 上限的版本。

### 4.4 归零表现

数字进入危险区时：

| 范围 | 表现 |
|---|---|
| 31 以上 | 正常 |
| 11～30 | 数字变为警告色，节拍音增强 |
| 1～10 | 每次行动强烈闪烁，个位数独立播报 |
| 0 | 时间冻结 0.3 秒，数字碎裂，进入失败 |

表现不得遮挡敌人意图或行动预览。

## 5. 网格与移动系统

### 5.1 地图规则

- 正方形网格。
- 仅允许上下左右四方向移动。
- 一次输入只移动一格。
- 墙、关闭的门和占位实体不可进入。
- 普通敌人和玩家不能占据同一格。
- 关卡边界外视为不可通行。

### 5.2 移动流程

1. 读取目标格。
2. 检查格子存在且可通行。
3. 检查没有阻挡实体。
4. 检查支付 1 后玩家数字仍大于 0。
5. 更新逻辑坐标与占用关系。
6. 支付成本并播放移动表现。
7. 进入环境和敌人结算。

无效输入不收费、不推进回合，例如撞墙或点击不可达格。

### 5.3 路线预览

鼠标/手柄选中一个可达格时：

- 用路径线显示最短路径。
- 显示纯移动成本。
- 不自动把战斗风险计算成保证值，但标出会进入的敌人攻击范围。
- 若路径会让玩家归零，路径末端显示红色禁止标记。

首个版本可只支持相邻格预览；完整路径预览列为增强项。

### 5.4 验收标准

- 每次成功移动只扣 1。
- 撞墙、越界、移动到占用格不扣数字。
- 逻辑位置先于下一回合敌人寻路更新。
- 门开启后，对应格在同一回合正确变为可通行。

## 6. 玩家攻击系统

### 6.1 普通攻击

- 目标：相邻一格内的一个敌人。
- 成本：玩家数字 2。
- 效果：敌人数字 -2，破防格 -1。
- 命中：必定命中。
- 不支持空挥；没有合法目标时攻击不成立且不收费。

### 6.2 击杀与夺取

当敌人破防格降到 0：

1. 记录敌人此刻的剩余数字。
2. 将敌人标为死亡，立即取消其本回合意图。
3. 从网格移除占用。
4. 将其剩余数字转移给玩家。
5. 应用玩家数字上限。
6. 更新门和关卡目标。
7. 播放数字从敌人飞向玩家的表现。

如果敌人数字先降到 0：

- 敌人立即“自然归零”并消失。
- 玩家不能获得任何数字。
- 是否计入守门击杀：默认 **不计入**，必须由玩家打破最后一格才算击杀。

### 6.3 战斗预览

瞄准敌人时必须显示：

- 本次攻击后玩家数字。
- 敌人攻击后剩余数字。
- 敌人剩余破防格。
- 若本击击杀：实际夺取值、玩家最终数字和溢出值。
- 本次攻击后敌人阶段可能命中玩家时，显示 `-10` 风险。

### 6.4 净收益公式

若敌人不移动、不攻击，且需要 `H` 次攻击：

```text
击杀时敌人剩余数字 = max(0, 初始敌人数 - 2H)
纯战斗净收益 = 击杀时敌人剩余数字 - 2H
                 = 初始敌人数 - 4H
```

完整路线收益：

```text
总净收益 = 夺取值 - 攻击成本 - 绕路步数 - 受到伤害总值
```

关卡设计者应让：

- 明显优质目标的预计总净收益为 +4～+12。
- 边缘目标为 -2～+3。
- 陷阱目标低于 -3，但风险必须可读。

## 7. 敌人系统

### 7.1 通用数据

| 字段 | 说明 |
|---|---|
| `EnemyId` | 数据表唯一 ID |
| `DisplayName` | 显示名称 |
| `CurrentNumber` | 当前可见数字 |
| `BreakPoints` | 当前破防格 |
| `MaxBreakPoints` | 初始破防格 |
| `MoveCost` | 敌人移动时消耗的自身数字，默认 1 |
| `AttackCost` | 敌人攻击时消耗的自身数字，默认 2 |
| `Damage` | 命中玩家造成的数字损失，默认 10 |
| `DetectionRange` | 激活范围 |
| `AttackRange` | 攻击范围 |
| `MoveRange` | 每个敌人阶段移动格数，MVP 固定 1 |
| `TurnOrder` | 固定行动顺序 |
| `IsGateTarget` | 是否计入门条件 |
| `BehaviorType` | 行为类型 |

### 7.2 敌人的数字消耗

敌人的有效行动也消耗其头顶数字：

- 移动一格：敌人数字 -1。
- 发动攻击：敌人数字 -2。
- 被玩家攻击：敌人数字 -2。
- 降到 0：敌人自然归零，不提供夺取。

因此拖延虽然可能让敌人消失，却也会失去收益；快速击杀能拿到更多数字。

### 7.3 激活规则

- 未激活敌人保持原地，不消耗数字。
- 玩家进入其检测范围或攻击它时激活。
- 激活后保持激活，不会脱战重置。
- 敌人意图在玩家行动前公开显示。

### 7.4 MVP 敌人原型

#### A. 枯竭者（低价值障碍）

- 数字：3
- 破防格：1
- 行为：原地警戒，相邻时攻击
- 用途：教会玩家“不是所有敌人都值得打”

#### B. 携时者（标准收益目标）

- 数字：18
- 破防格：3
- 行为：激活后向玩家移动，相邻时攻击
- 用途：复现核心示例，作为标准价值单位

#### C. 计时炮塔（位置风险）

- 数字：16
- 破防格：2
- 行为：不移动，直线 3 格攻击；攻击前一回合显示射线
- 用途：让路线选择比单纯距离更重要

#### D. 守门者（高价值必选目标）

- 数字：28
- 破防格：4
- 行为：追击；每隔一回合蓄力，下一击伤害 20
- 用途：三选二开启 Boss 门

### 7.5 敌人 AI 决策优先级

普通追击敌人每回合：

1. 若能攻击玩家，攻击。
2. 否则若存在到玩家的路径，沿固定最短路径移动 1 格。
3. 否则等待。

最短路径存在同长度选择时，固定按 **上、右、下、左** 选择，保证可预测。

### 7.6 意图显示

敌人头顶同时显示：

- 大号当前数字。
- 小型破防格。
- 下一步意图图标：移动、攻击、蓄力、等待。
- 攻击目标格或射线范围。

玩家无需打开详情面板即可判断下一回合风险。

## 8. 伤害与危险系统

### 8.1 敌人攻击

- 敌人支付自己的攻击成本后发动攻击。
- 攻击必定命中当时仍在目标格的玩家。
- 普通命中使玩家数字 -10。
- 敌人支付成本后若自己归零，攻击仍然完成，随后敌人消失。

### 8.2 预告攻击

炮塔、精英和 Boss 的范围攻击遵循：

1. 第 N 回合显示危险格。
2. 玩家执行一次行动。
3. 敌人阶段攻击仍处于危险格的玩家。

危险格必须用颜色和图形双重表达，避免只依赖红绿色。

### 8.3 环境危险

首个版本最多保留一种：

- **倒计时地板**：进入时额外 -3，地块上明确显示 `-3`。

若关卡已足够复杂，MVP 删除环境危险，优先保证敌人价值计算清楚。

## 9. 门与关卡目标系统

### 9.1 门条件框架

门条件做成可配置组合：

- 击杀指定敌人。
- 在一组守门者中击杀至少 N 个。
- 玩家当前数字至少为 N。
- 激活指定地图机关。

门本身不消耗新的货币，也不产生钥匙道具。

### 9.2 首关使用的条件

Boss 门前布置 3 个守门者，玩家击杀其中任意 2 个后开门：

- 三个守门者的数字、破防格和路线风险不同。
- 玩家可以选择收益更高但更远的目标，或收益低但更安全的目标。
- 被自然归零的守门者不计入击杀。
- 条件完成后门永久开启。

### 9.3 门反馈

门上直接显示 `0/2`、`1/2`、`2/2`：

- 击杀有效目标后立即更新。
- 条件满足时播放贯穿地图可见/可听的开启反馈。
- 地图视野内始终可以判断 Boss 方向。

### 9.4 验收标准

- 任意两个有效守门击杀都能开门。
- 自然归零不增加计数。
- 条件完成前门格不可走，完成后立即可走。
- 门打开后保存状态，不会因场景内其他敌人变化重新关闭。

## 10. Boss 系统

### 10.1 Boss 目标

Boss 检验三件事：

- 玩家是否带着足够数字到达。
- 玩家是否理解“攻击也在倒计时”。
- 玩家是否会用移动躲避预告，而不是硬吃伤害。

### 10.2 MVP Boss：零号执行者

默认属性：

| 属性 | 数值 |
|---|---:|
| 破防格 | 6 |
| 数字 | 不显示/不可夺取 |
| 普通攻击伤害 | 10 |
| 强攻击伤害 | 20 |
| 攻击循环 | 3 回合 |

循环：

1. **锁定**：预告十字形危险区，Boss 不攻击。
2. **执行**：攻击预告区。
3. **回收**：向玩家移动 1 格或等待。
4. 回到锁定。

玩家每次普通攻击仍支付 2，并削除 Boss 1 格破防。击杀 Boss 至少需要 12 点攻击成本，额外移动和失误另算。

### 10.3 Boss 特殊规则

- Boss 不提供数字，避免胜利后的奖励失去意义。
- Boss 的所有危险范围提前一回合显示。
- Boss 不得随机选择攻击模式；模式循环固定。
- Boss 被击杀后取消尚未结算的攻击。
- Boss 死亡且玩家数字大于 0，立即胜利。

### 10.4 Boss 难度基线

理想首胜：

- 玩家进门时剩余 25～40。
- Boss 房移动 5～10 步。
- 攻击 6 次，成本 12。
- 熟练玩家不受伤，结束时剩余 8～23。
- 普通玩家允许承受 1 次伤害仍有机会胜利。

## 11. 关卡结构

### 11.1 单关垂直切片

首个完整关卡分为五段：

1. **教学走廊**  
   通过 5～8 步移动让玩家看到数字下降。
2. **价值教学**  
   同时展示数字 3/破防 1 与数字 18/破防 3 的敌人。
3. **路线选择区**  
   两条路线：近但危险，远但存在高收益敌人。
4. **守门区**  
   3 个守门者中选择 2 个击杀。
5. **Boss 房**  
   小型开放竞技场，固定预告循环。

### 11.2 地图预算

首轮灰盒建议：

| 项目 | 数量 |
|---|---:|
| 地图有效格尺寸 | 24×18 左右 |
| 必经移动成本 | 35～45 |
| 可选绕路成本 | 每条 4～12 |
| 普通敌人 | 4～6 |
| 守门者 | 3 |
| 炮塔 | 1～2 |
| Boss | 1 |

### 11.3 关卡公平性

- 起点必须能看见第一个敌人数字和 Boss 门方向。
- 在做路线选择前，应能看见相关敌人的数字、破防格和危险范围。
- 禁止进入后才揭示不可避免的 10 点伤害。
- 至少存在一条不依赖受伤、理论上能通关的路线。
- 最优路线不能要求像素级操作，只要求正确决策。

## 12. UI 与信息架构

### 12.1 常驻 HUD

必须常驻：

- 玩家当前数字：屏幕最显眼信息。
- 当前行动预览：例如 `64 → 62`。
- Boss 门进度：例如 `守门者 1/2`。
- 暂停/重新开始入口。

不制作传统血条、蓝条、金币栏或经验栏。

### 12.2 世界空间 UI

普通敌人头顶：

```text
   18
  ◆◆◆
   ⚔
```

- `18`：剩余数字。
- `◆◆◆`：破防格。
- `⚔`：下一回合意图。

数字夺取时，敌人数字拆分成字符或粒子飞向玩家 HUD；玩家数字在粒子到达时增加。

### 12.3 行动预览颜色

- 白色：无风险、普通消耗。
- 青色：结算后数字增加。
- 黄色：进入敌人威胁区。
- 红色：会归零或受到确定伤害。

同时使用符号和文本，不只依赖颜色。

### 12.4 教学文本

只使用短句，按需出现：

1. `每走一步，数字 -1`
2. `攻击消耗 2`
3. `打破全部标记，夺走敌人的剩余数字`
4. `不是每个敌人都值得杀`
5. `归零之前，杀死 Boss`

每条只出现一次，可在暂停菜单重看。

## 13. 音频、镜头与视觉反馈

### 13.1 数字反馈优先级

任何数字变化都应同时具备：

- 数字跳变动画。
- 明确的 `-1`、`-2`、`-10` 或 `+12` 飘字。
- 与幅度匹配的音效。

不得只用粒子而不显示具体数值。

### 13.2 音频节拍

- 背景音乐维持稳定节拍，强化“每一步都是倒计时”。
- 数字低于 30 后加入节拍层。
- 数字低于 10 后每次行动播放清晰计数音。
- 数字增加时节拍短暂反向或上扬。

### 13.3 镜头

- 普通移动不震屏。
- 受到 10/20 伤害时使用两级短震动。
- 击杀高价值敌人和开门时短暂聚焦，但总时长不超过 0.5 秒。
- Boss 死亡时允许 1～2 秒终结演出。

## 14. 游戏状态与流程

### 14.1 状态

```text
Title
  → Tutorial/Gameplay
      → Paused
      → Victory
      → Defeat
```

Gameplay 内部：

```text
AwaitingInput
→ Previewing
→ ResolvingPlayer
→ ResolvingEnvironment
→ ResolvingEnemies
→ CheckingOutcome
→ AwaitingInput
```

### 14.2 失败

触发条件：

- 玩家数字小于等于 0。
- 玩家没有任何合法行动且 Boss 未死。

失败界面显示：

- 到达区域。
- 击杀数。
- 夺取总数字。
- 消耗构成：移动、攻击、受伤。
- `立即重试`，默认选中。

### 14.3 胜利

触发条件：

- Boss 死亡。
- 玩家数字大于 0。

胜利界面优先显示：

- `剩余数字：N`
- `总行动数`
- `承受伤害`
- `重新挑战`

剩余数字天然充当分数，不另设积分货币。

### 14.4 重开

- 任意时刻可暂停并重新开始关卡。
- 重开应在 2 秒内回到可操作状态。
- 所有敌人数字、位置、门和教学触发器恢复初始值。

## 17. MVP 制作顺序

### P0：核心可玩（必须）

1. 网格输入与一步移动。
2. 玩家数字显示与移动扣 1。
3. 相邻攻击扣 2。
4. 敌人数字、破防格和击杀夺取。
5. 玩家归零失败与一键重开。
6. 至少两类敌人：数字 3 与数字 18。
7. 守门击杀条件与门开启。
8. 固定循环 Boss 与胜利。
9. 一个从 100 开始、可完整通关的灰盒关卡。

### P1：可读性与公平（强烈建议）

1. 敌人意图显示。
2. 攻击与移动结算预览。
3. 炮塔预告范围。
4. 数字变化音效、飘字和危险区反馈。
5. 失败统计。
6. 首次游玩教学短句。

### P2：打磨（有时间再做）

1. 完整路径成本预览。
2. 更多敌人行为。
3. 音乐随数字分层。
4. Boss 终结演出。
5. 最佳剩余数字记录。
6. 手柄完整支持和辅助功能选项。

### 明确砍掉

时间不足时首先砍：

1. 环境陷阱。
2. 第四种普通敌人。
3. 多关卡。
4. 剧情对话。
5. 随机内容。

不得砍掉敌人数值预览、破防格和行动成本反馈；这些是核心玩法本身。

## 18. 测试与验收清单

### 18.1 数字系统

- [ ] 玩家从 100 开始。
- [ ] 成功移动一次变为 99。
- [ ] 成功攻击一次额外减少 2。
- [ ] 普通受击准确减少 10。
- [ ] 数字变化都带有原因记录。
- [ ] 任何主动行为都不能让玩家主动降到 0。
- [ ] 夺取不会超过上限，溢出显示正确。

### 18.2 战斗系统

- [ ] 数字 18、破防 3 的敌人被攻击三次后剩 12。
- [ ] 击杀后玩家准确获得 12。
- [ ] 数字 3、破防 1 的敌人被击杀后只提供 1。
- [ ] 击杀敌人后，它不会在同一回合继续行动。
- [ ] 自然归零敌人不提供数字。
- [ ] 预览结果与实际结算完全一致。

### 18.3 回合与 AI

- [ ] 每次玩家有效行动只推进一个敌人阶段。
- [ ] 无效输入不推进敌人阶段。
- [ ] 多敌人行动顺序固定。
- [ ] 相同输入序列可复现相同结果。
- [ ] 敌人意图在行动前可见。

### 18.4 关卡目标

- [ ] 三个守门者中任意击杀两个可以开门。
- [ ] 自然归零的守门者不计数。
- [ ] Boss 门开启后可正常寻路通过。
- [ ] Boss 死亡时玩家大于 0 才胜利。
- [ ] 至少存在一条无伤通关路线。

### 18.5 体验目标

找 3～5 名未参与开发的试玩者，观察：

- [ ] 30 秒内理解移动会减少数字。
- [ ] 2 分钟内理解敌人数字是可夺取资源。
- [ ] 至少一次主动绕过低价值敌人。
- [ ] 在失败后能说出自己在哪类成本上浪费了数字。
- [ ] 第一局在 8～12 分钟内结束。
- [ ] 第二局明显比第一局剩余数字更多或走得更远。

## 19. 平衡流程

### 19.1 记录项

每局开发日志记录：

- 每一步的位置与行动类型。
- 玩家每次数字变化及原因。
- 每个敌人的初始数字、击杀时数字或自然归零。
- 玩家进入 Boss 房时的数字。
- Boss 战受击次数。
- 胜负和最终剩余数字。

### 19.2 调整顺序

发现关卡过难时，按以下顺序调整：

1. 减少不可避免的移动距离。
2. 提高可选优质敌人的数字。
3. 降低守门者破防格。
4. 降低敌人伤害。
5. 最后才提高玩家初始数字。

这样能保留“100 倒计时”的主题识别度。

### 19.3 首轮目标数据

| 指标 | 目标 |
|---|---|
| 第一次游玩通关率 | 20%～40% |
| 第二或第三次通关率 | 60%～80% |
| 熟练玩家进 Boss 房数字 | 25～40 |
| 熟练玩家最终数字 | 8～23 |
| 单局时长 | 8～12 分钟 |
| 有意义路线选择 | 至少 3 次 |

## 20. 原型完成定义

只有同时满足以下条件，才算核心原型成立：

1. 玩家能仅通过地图信息，在行动前算出敌人是否值得击杀。
2. 数字 18 的示例在游戏中严格得到“花 6、夺 12”的结果。
3. 绕过数字 3 的敌人通常优于击杀它。
4. 至少存在两条成本和风险不同的可行路线。
5. 门迫使玩家选择击杀目标，而不是清空全图。
6. Boss 战要求玩家在攻击成本与躲避成本之间取舍。
7. 玩家失败后能理解自己为何归零，并愿意立刻用新路线重试。

## 21. 待试玩验证的设计决策

以下内容已给出默认值，但不应在第一次试玩前投入大量表现成本：

1. **敌人行动是否消耗自身数字**  
   默认：消耗。验证玩家是否能理解“拖延会降低战利品”。
2. **玩家数字上限是否需要 199**  
   默认：需要。验证是否真的会出现失控囤积。
3. **Boss 是否显示数字**  
   默认：不显示，只显示 6 格破防。若破坏统一性，可改为特殊倒计时。
4. **守门者三选二是否产生真实选择**  
   若玩家永远选同两个，调整位置、数字和破防格，而不是增加随机性。
5. **敌人同时显示数字、破防格和意图是否过载**  
   若过载，优先保留数字和意图；破防格可在选中时放大，但不能隐藏。

每次修改这些规则时，应同步更新本文件第 2 节规则表和第 18 节验收用例。
